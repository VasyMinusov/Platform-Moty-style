# ORDO — фронтенд для CTF Training Platform

React + Vite фронтенд поверх FastAPI-бэкенда из `ctf-platform`. Дизайн — тема
«оперативного досье»: список заданий выглядит как картотека личных дел,
статус инстанса — как штамп в деле.

## Возможности

- Регистрация и вход (JWT, хранится в `localStorage`).
- Список заданий с фильтрами по категории и статусу решения.
- Запуск / остановка персонального инстанса задания, обратный отсчёт TTL.
- Отправка флага, начисление очков.
- Профиль: сводка очков и список решённых заданий (считается на фронте из
  `GET /challenges`, т.к. отдельного `/auth/me` в API нет — см. ниже).
- Админ-панель: синхронизация заданий и очистка просроченных инстансов
  (`POST /admin/challenges/sync`, `POST /admin/instances/reap`). Доступ
  проверяется бэкендом — обычный пользователь увидит ошибку 403.

## Запуск в разработке

```bash
pnpm install
pnpm dev
```

По умолчанию `VITE_API_URL=/api`, а `vite.config.js` проксирует `/api/*` на
`http://localhost:8000` (и срезает префикс `/api`, т.к. роутеры бэкенда
живут без него: `/auth`, `/challenges`, `/admin`). Поэтому для локальной
разработки достаточно поднять бэкенд отдельно (`docker compose up backend db`
или напрямую `uvicorn`) на порту 8000 — менять `.env` не нужно.

## Сборка

```bash
pnpm build   # -> dist/
pnpm preview # локальный просмотр собранной версии
```

## Интеграция в docker-compose.yml платформы

Сейчас `nginx.conf` в `ctf-platform` проксирует `/` напрямую на backend —
фронтенда там ещё нет. Чтобы подключить этот репозиторий:

1. Склонируйте/положите этот фронтенд рядом с `ctf-platform`, например
   `ctf-platform/../ctf-frontend`.
2. Добавьте сервис `frontend` в `docker-compose.yml` — пример в
   `deploy/docker-compose.patch.yml`.
3. Замените `nginx/nginx.conf` в `ctf-platform` на `deploy/nginx.conf` из
   этого репозитория — он раздаёт собранный фронтенд на `/` и проксирует
   `/api/*` на backend.
4. `docker compose up --build` — платформа будет доступна на `http://localhost/`.

## Известное ограничение API (не блокирует работу, но стоит учитывать)

В бэкенде нет эндпоинта `GET /auth/me`, поэтому фронтенд не знает роль
(`student`/`admin`) и точные `points` пользователя без дополнительного
запроса — они выводятся из локального декодирования JWT (`sub`) и из
списка `/challenges` (сумма очков решённых заданий). Если добавите
`GET /auth/me`, возвращающий `UserOut` — будет легко подключить в
`src/context/AuthContext.jsx` и `src/pages/ProfilePage.jsx`, и админ-раздел
можно будет скрывать по роли на фронте, а не только полагаться на 403 с бэка.

## Структура

```
src/
├── api/          # клиент к бэкенду (fetch-обёртка), декодер JWT
├── context/       # AuthContext — токен, логин/регистрация/логаут
├── components/    # Layout, ChallengeCard, RequireAuth
├── pages/         # Login, Register, Challenges, Profile, Admin, 404
└── styles/        # design tokens (палитра, типографика)
```
